## Architecture assessment

Retain the **19-table** recommendation. Eleven domain tables preserve children, restricted child profile, caregiver, child/caregiver association, programme changes, questionnaire response/item/answer, attendance, support observation and ADL grains. One scoped reference table consolidates controlled values. Three source tables preserve file versions, rows and typed provenance. Membership, identity candidates, recovery actions and audit history provide the four remaining security/evidence functions. Supabase-managed Auth tables are excluded from this count.

UUID keys separate relational references from exact unique child/caregiver business IDs. Child/caregiver is many-to-many capacity; observed data do not prove one caregiver already has several children. Child private profile is optional one-to-one. Response references one validated child/caregiver association, and composite definition FKs prevent mixing questionnaire definitions. Source provenance selects exactly one typed target. Repeated observations remain separate; a child/date uniqueness rule is not invented. Candidate identity evidence never becomes a child FK solely from name equality.

Activity event/planning grain remains unresolved, so the dedicated activity table stays deferred and its original content remains in source rows. No table was removed simply to reach a count. The single redundant child_caregivers(child_id) index was removed because unique(child_id,caregiver_id) already covers that prefix. The complete 5,186-coordinate source mapping, previous raw/organized comparison, and original 12/17-table models remain preserved. Reference-only retention is not a complete future form or analytical projection.

Future forms can use stable IDs, approved options and explicit review states. Private caregiver directory/form projections, scoring and event definitions require later approval. No frontend was built.
